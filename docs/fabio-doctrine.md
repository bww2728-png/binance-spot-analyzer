# عقيدة Fabio — المواصفة الملزمة لمحرك الفرص الحية (واجهة الفرص الحية فقط)

> هذه الوثيقة **مرجع ملزم** قبل أي كود. كل تعريف هنا قابل للاختبار.
> القاعدة الذهبية: **"النظام صحيح برمجيًا" ≠ "الاستراتيجية مربحة"** —
> الاختبارات تثبت تنفيذ العقيدة كما كُتبت، ولا تثبت Edge إلا عبر OOS وwalk-forward
> وعينة كبيرة ورسوم/انزلاق ومقارنة المقبول بالمرفوض.
> والتوأم: **الدقة على العينة المرئية ≠ التعميم** (لهذا: مجموعة عمياء + OOS).

## 1) الفكرة الأساسية

النظام لا يقول «وصل السعر إلى SSL = شراء» ولا «حدث Sweep = شراء».
بل يقرأ القصة كاملة:
`منطقة SSL → وصول السعر → سحب السيولة → رفض → عودة → قراءة المشترين والبائعين → تأكيد القوة → دخول فقط عند اتفاق الأدلة.`

## 2) التسلسل الحرفي الإلزامي (آلة حالة)

```
SSL → Sweep → Reclaim (≤ reclaimWindowBars, شموع + زمن فعلي) → Flow Confirmation → Entry
```

- أي `published` لم يمر بهذا التسلسل كاملا = **خلل حرج يُسقط البناء** (assertion)، لا سجل صامت.
- الممنوع حرفيا: `SSL → Sweep → Buy`.

## 3) السويب الناجح مقابل الفاشل (فرضية قابلة للقياس، لا حقيقة)

- **ناجح**: نزول تحت SSL + أخذ السيولة + رفض البقاء + عودة فوق المرجعي
  خلال `reclaimWindowBars` (التجربة: `{3, 4, 6}` بنفس البيانات وعزل باقي العوامل).
- **فاشل**: أخذ السيولة ثم تعامُل السوق مع السعر تحتها كمقبول (لا استعادة ضمن النافذة، أو كسر حقيقي بمسافة `breakAtr × ATR`).
- **الفاشل لا يُحذف**: يُخفى من العرض مع عدّاد مرئي، ويُحفظ في الخلفية كمعلومة عن سلوك المنطقة (لا يتحول لفرصة شراء أبدا).
- **الزمن المزدوج إلزامي**: كل `reclaim` يسجل **عدد الشموع + الزمن الفعلي** (3 شموع على 1m = 3 دقائق ≠ 45 دقيقة على 15m).

### خريطة النوافذ الحالية (تُوثَّق قبل أي تغيير — ممنوع التغيير المزدوج)

| المعامل | الموقع | الدور | القيمة اليوم |
|---|---|---|---|
| `freshnessBars` | `server/live-opportunities/tracker.mjs` (تهيئة الحالة) | صلاحية حالة swept متتبعة | 6 |
| `maxReclaimBars` (حي) | `server/live-opportunities/loop.mjs` config | نافذة الاستعادة الحية | 6 |

القاعدة: تُغيَّر التجربة **واحدا واحدا** مع إعلان الأثر؛ أي تغيير مزدوج مرفوض في المراجعة.

## 4) أدوات التأكيد بعد السويب (منهج Fabio)

| الأداة | السؤال | الحالة في الكود |
|---|---|---|
| Aggression | أوامر شراء قوية فعلية؟ | ضمن `flowScore` — يُفصَّل كمؤشر مستقل |
| Bubbles / Big Trades | صفقات شراء كبيرة قرب المنطقة؟ | مكوّن موجود داخل `flowScore` (`scanner.mjs`) — يُفصَّل ويُوثَّق |
| Delta | المشترون الطرف الأكثر عدوانية؟ | **غير مؤكد كمؤشر مستقل — يُجرد أولا** |
| CVD | ضغط الشراء العام يتحسن؟ | موجود (`liquidity/derivatives.mjs`) |
| Absorption | امتصاص للبيع القوي؟ | **غير مؤكد — يُجرد أولا** |
| Follow-Through | الأدلة أدت لحركة سعرية فعلية؟ | **غير مؤكد — يُجرد أولا** |

قاعدة: **Aggression بدون نتيجة سعرية ≠ Aggression حرّكت السوق** (تُسجَّل الدرجتان منفصلتين).

## 5) Volume Profile / POC / LVN — للمسار لا للاكتشاف

- `POC`: أكبر حجم تداول. `Value Area`: منطقة القبول. `LVN`: تداول قليل → حركة سريعة.
- الاستخدام الوحيد: **تقييم جودة الطريق إلى الهدف** — لا تستبدل منطق تحديد SSL.
- موجود: `liquidity/volumeProfile.mjs` (POC/VA/LVN) + `classifyLocation` (balance/imbalance).

## 6) Balance / Imbalance وFailed Auction

- `balance`: ذهاب وعودة → لا مطاردة. `imbalance`: طرف أقوى → بيئة أفضل بعد Reclaim + Aggression.
- **Failed Auction ≠ SSL Sweep** — تعريفان منفصلان، وخلطهما خطأ تصنيفي يُسقط المراجعة.

## 7) شروط المنع (Veto — خارج الدرجة دائما)

حتى مع سويب ناجح، لا دخول عند أيٍّ منها (تُسجَّل مع كل رفض في قسم المرفوضات):

1. لا Aggression. 2. Delta لا يدعم. 3. CVD يعاكس بقوة. 4. فقاعات شراء بلا حركة.
5. Follow-Through ضعيف. 6. عودة السعر لـSSL مباشرة. 7. هدف/منطقة معاكسة قوية قريبة.
8. نظام/جلسة غير مناسبة (فتكة سيولة). 9. الفرصة تأخرت (انتهت النافذة).

## 8) الفصل المعماري الإلزامي: Gates → Eligibility → Ranking

```
Vetoes/Gates (إسقاط) → Eligibility (مؤهل/غير مؤهل) → Ranking Score (ترتيب المؤهلين فقط)
```

- كل عامل يُوسم: `veto` أم `ranking` أم الاثنان — بلا استثناء.
- `gates()` الحالية (`scanner.mjs:261`) نواة الـveto — تُوسَّع بالشروط التسعة.
- `compositeScore` الجمعية (`scanner.mjs:246`) للترتيب فقط — **ممنوع ذوبان أي veto فيها**.
- تحذير المضاعفة: أي صيغة ضربية جديدة (`P×R×...`) تُطبَّع كل عواملها إلى [0,1] بأوزان
  مسجلة وسقوف، وتجتاز اختبار الحساسية (±20% لأي عامل يجب ألا يقلب الترتيب جذريا).

## 9) ترتيب الأدلة (11 مستوى = ترتيب الحساب، لا أوزان متساوية)

1. SSL (منطقنا). 2. Sweep. 3. Reclaim. 4. Aggression. 5. Delta/Bubbles/Big Trades.
6. CVD. 7. Absorption. 8. Follow-Through. 9. Volume Profile/POC/VA/LVN.
10. Balance/Imbalance. 11. مسار الهدف والسيولة المقابلة. ثم: Entry Decision.

## 10) معادلة الترتيب المعتمدة

```
rank = P(نجاح|شريحة) × R × (1 / الوسيط_المشروط_للمدة) × جودة_المسار
جودة_المسار = جودة_SSL × جودة_السويب × تأكيد_الفلو × توافق_الاتجاه
```

- **الوسيط لا المتوسط** (مقاومة الشواذ)، ومشروط بـ `(symbol|TF|model|session|regime|target)`.
- تحت حد العينة: **انكماش نحو الوسيط العام** — لا رقم وهمي ولا حذف صامت.
- المدة تُعرض **نطاقا + ثقة** ("عادة 20-50 دقيقة") — لا وقت دقيق أبدا.

## 11) إزالة التكرار عبر الفريمات

- مفتاح الحدث: `(symbol | liquidityLevel | sweepAt)` + قائمة الفريمات الشاهدة.
- معيار عدم الدمج يُكتب قبل الكود (إعدادان مستقلان حقا لا يُدمجان).

## 12) الذاكرة: السلسلة الكاملة لا الفرص فقط

```
Zone → Sweep → Reclaim → Confirmation → Opportunity → Outcome
```

بمعرفات سببية (كل حلقة تشير لسابقتها) — لدراسة "لماذا نجح/فشل السويب" لاحقا،
لا نتيجة الصفقة فقط. القبول: قتل قسري مع 5 نشطة → عودة الخمس بحالاتها وأزمنتها.

## 13) التغطية بالأسباب (لا نسبة عمياء)

```
Coverage = analyzed / eligible
```

مع عدّادات الاستبعاد: لا بيانات / لا SSL / لا Sweep / تعارض HTF /
R:R ناقص / فلو غير مؤكد / معايرة ناقصة. (البنية `phases` + `rejected` موجودة — تُستكمل.)

## 14) المعايرة: بوابة التداول ≠ الحذف من البحث

- `minSegmentTrades = 8` بوابة تداول فقط.
- الشرائح ذات 5-6 حالات: **محجوبة عن النشر + ظاهرة في البحث** بوسمها.
- دقة الحقول اليوم (`client/src/lib/types.ts` — لا تُعمَّم): `BuyCalibrationSegment.tier`
  وحده يقبل `qualified|probationary|weak`؛ و`BuyOpportunity.tier` و`BuyHistoryEvent.tier`
  يقبلان `qualified|probationary|null` فقط (بلا `weak`)؛ و`durationMs` موجود فقط في
  `BuyHistoryEvent`؛ و`BuyWatchRow` بلا `tier` أصلا — أي وسم جديد (مثلا `weak` للفرص)
  يتطلب توسيع الأنواع صراحة في المرحلة 5.

## 15) الاختبارات الملزمة

1. دخان: 20 حالة مصنفة (10/10) → تطابق 100%.
2. عمياء: بروتوكول `docs/blind-protocol.md` (تسمية/تنفيذ عمياني/تصحيح) — تُدار خارج الكود.
3. التكافؤ: Live = Replay = Backtest (Sweep/Reclaim/Confirmation/Entry/Invalidation/Outcome).
4. الحساسية: ±20% لأي عامل ترتيب → لا انقلاب جذري.
5. OOS لاحقا: walk-forward + رسوم/انزلاق (غائبان اليوم في `server/backtest/`) + مقارنة مقبول/مرفوض + سلة (BTC ثم ETH + أنظمة).

## 16) كيف يفكر النظام (تلخيص تنفيذي)

```
❌ لا: «وجدت Sweep → اشتري»
✅ بل: «SSL → سحب → رجوع سريع → مشترون فعليون → Delta/CVD يدعمان →
 Follow-Through → لا عوائق → جودة عالية → دخول»
«Sweep بلا Aggression» → راقب ولا تدخل.
«Sweep + Reclaim ثم اختفت القوة» → الفرصة ضعفت.
```

**الأدوار**: أنت تحدد «أين» (SSL). السويب يحدد «ماذا حدث».
أدوات Fabio تحدد «من يضغط وهل الحركة حقيقية». النظام يقرر «هل يستحق الدخول؟».
