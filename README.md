# Binance Spot Analyzer

منصّة تحليل **Binance Spot** بواجهة عربية: كشف مناطق السيولة (SSL)، محاكاة السويب،
متابعة الفرص الحية بآلة حالة، معايرة إحصائية مستمرة، وتصنيف شرعي للأصول.

> **تنبيه:** هذا نظام تحليل ومراقبة، لا منفّذ أوامر. لا يملك مفاتيح تداول ولا يرسل أوامر
> إلى Binance.

## المعمارية

```
Binance REST/WS ──► market/ (streams + candleStore)
                         │
                         ▼
              liquidity-zones/ (كشف + محاكاة سويب)
                         │
                         ▼
              live-opportunities/ (scanner → tracker → loop)
                         │        ↳ recovery.mjs (استعادة قبل بدء المحرك)
                         ▼
            Express 5 (server/index.js) ──► Supabase REST (Postgres)
                         │
                         ▼
                 React + Vite (client/)
```

| الطبقة | المسار | المسؤولية |
|---|---|---|
| الخادم | `server/index.js` | تجميع المحركات ومسارات API (87 مساراً) |
| التخزين | `server/db.js` | Supabase REST بلا ORM + الأحداث + الصفحات |
| بيانات السوق | `server/market/` | بث WS اختياري، بذر REST، مخزن الشموع |
| السيولة | `server/liquidity-zones/`, `server/liquidity/` | كشف المناطق ومنطقها |
| الفرص الحية | `server/live-opportunities/` | scanner · tracker · loop · recovery · lifecycle |
| استراتيجيتي | `server/strategy2/` | HTF×8، قمم/قيعان محمية، choch، ديسكاونت |
| المعايرة والاحتفاظ | `server/services/` | ترقية الشرائح، سياسة الحذف، ملخصات |
| الشرعي | `shared/shariahCore.mjs` | قواعد التصنيف المشتركة بين الطرفين |
| الواجهة | `client/src/` | 41 مكوّناً، 13 شاشة، حالة مركزية عبر zustand |

الوثيقة المرجعية الملزمة لمنطق القرار: [`docs/fabio-doctrine.md`](docs/fabio-doctrine.md).

## التشغيل المحلي

المتطلّبات: **Node 22+**.

```bash
npm ci
npm ci --prefix server
npm ci --prefix client

cp .env.example .env      # ثم اضبط SUPABASE_URL و SUPABASE_ANON_KEY
npm run dev               # server + client معاً
```

بدون `SUPABASE_URL`/`SUPABASE_ANON_KEY` تعمل العملية لكن **بلا تخزين ولا استعادة**،
و`/readyz` تُعيد `503` — وهذا مقصود ليُعلن التدهور بدل أن يبدو النظام سليماً.

خادم فقط: `npm run server` · واجهة فقط: `npm run client`.

### أهم متغيّرات البيئة

| المتغيّر | الأثر |
|---|---|
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | التخزين والاستعادة (إلزاميان للعمل الكامل) |
| `PORT` | منفذ الخادم (افتراضي 8787 محلياً؛ `Dockerfile` يضبط 8080) |
| `LIGHT_MODE=1` | تعطيل workbench + بث السوق + الفرص الحية + استراتيجيتي |
| `DETECT_MIN` | دورة الكشف الدوري بالدقائق (افتراضي 5) |
| `RETENTION_*` | سياسة الاحتفاظ (تشخيص 7 أيام، عيّنات 30، صور 90) |
| `LIVE_*` | حدود اشتراكات البث والمعايرة |

القائمة الكاملة مشروحة في [`.env.example`](.env.example).

## الاختبارات

```bash
npm test          # node --test server/tests/*.test.mjs
npm run lint      # typecheck للواجهة (tsc)
```

الحالة على خط الأساس `main @ 740dd36`: **638 ناجح / 0 فاشل / 2 متخطّى** من 640 اختباراً.
وبعد اختبارات هذا التدقيق: **658 ناجح / 0 فاشل / 2 متخطّى** من 660، على Node 22 (نسخة
النشر) وNode 24.
الاختبارات تشمل الاستعادة بعد إعادة التشغيل، وتكرار الأحداث، وسياسة الاحتفاظ،
ومطابقة محركي السيولة، وحدود الذاكرة، وتقييم الجاهزية.

CI (`.github/workflows/ci.yml`) يشغّل الاختبارات، وفحص صياغة كل وحدات الخادم،
وبناء الواجهة، وتدقيق اعتماديات الإنتاج — على كل Push و Pull Request.

## النشر

```bash
docker build -t bsa .
docker run -p 8080:8080 --env-file .env bsa
```

- `Dockerfile` متعدد المراحل: بناء الواجهة على `node:22-alpine` ثم صورة تشغيل.
- `NODE_OPTIONS=--max-old-space-size=640` مقصود: يترك هامشاً تحت حدّ الحاوية.
- `railway.json` يستخدم `/healthz` كـ healthcheck، والمنفذ 8080.

التفاصيل في [`DEPLOY.md`](DEPLOY.md).

## نقاط التشغيل

| المسار | المعنى | الحالة |
|---|---|---|
| `GET /healthz` | حياة العملية فقط (liveness) | 200 دائماً ما دامت العملية حيّة |
| `GET /readyz` | جاهزية حقيقية (readiness) | 503 عند غياب حزمة الواجهة، أو تخزين غير مضبوط، أو فشل استعادة الفرص الحية |
| `GET /api/health/deep` | لقطة تشخيصية كاملة (ذاكرة، تأخّر الحلقة، دورات المحركات) | 200 |
| `GET /api/shadow/report` | تقرير فروق الإصلاحات قبل تفعيلها | 200 |

`/readyz` لا تُسقط النظام بسبب بيانات سوق قديمة أو تعذّر البث (المسار الاحتياطي REST
سلوك مشروع) — تُبلّغ عنها كـ `degraded` فقط.

> **تحذير تشغيلي:** لا تُستخدم `/readyz` كـ `healthcheckPath` في منصة الاستضافة. أثناء
> الإقلاع تكون `503` عمداً (الاستعادة لم تكتمل بعد)، فربطها بحلقة الفحص يجعل كل نشر
> يدخل إعادة تشغيل لا تنتهي. `railway.json` يستخدم `/healthz` — وهذا صحيح ومقصود.

## نموذج الأمان

- **لا مصادقة بالتصميم.** كل مسارات `/api` مفتوحة، وسياسات RLS في Supabase تمنح دور
  `anon` كل الصلاحيات على الجداول.
- لذلك: **لا يُنشر هذا النظام على عنوان عام** قبل تنفيذ خطة التقوية في
  [`docs/security-hardening.md`](docs/security-hardening.md).
- مفتاح `anon` ليس سراً (يُضمَّن في حزمة الواجهة عادةً)؛ الأمان الحقيقي يأتي من تقييد
  الصلاحيات على الخادم لا من إخفاء المفتاح.
- لا توجد أسرار مُضمَّنة في الكود: كل المفاتيح تُقرأ من البيئة.
